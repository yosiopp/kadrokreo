# 計測（2026-11-24、全部の描き直し）

`npm run bench` の結果（`bench/out/latest.md` をそのまま写したもの）。値は操作 1 回ぶんのメインスレッドの時間（ms）。測り方は `bench/run.mjs` と `cli/bench/` の先頭のコメント。
その前の移り変わりは `2026-11-24-main-recolor.md`・`2026-11-24-store-preview.md` ほか。

- 環境: darwin arm64、Node v24、Chrome（ヘッドレス）、1440×900、deviceScaleFactor 2。同じマシンで続けて測った（値は揺れる。今回触っていない行の差は揺れ）
- 直す前は直前の main のビルドを `--no-build` で測った。どちらも今回足した行「全体表示のまわりでズームして止まり、描き直すまで」を含む bench で測っている
- 「全体表示のまわり」の行は揺れが大きい（p90 が中央値の 1.5〜2 倍）ので、large は直す前と後を交互にさらに 2 回ずつ測り、下の表には測った中央値の幅を載せた
- 「ズームして止まり、描き直すまで」は、その前のズームの計測で 10 段ほど拡大した所で測るので、文字が帯になる大きさを超えたものが多く、差は小さい

- 画面上の文字の大きさが 3 実ピクセル未満のテキストは、文字の代わりに文字色の薄い帯（行ごと、小文字の高さくらいの太さ、濃さ半分。回していなければ実ピクセルの境目に揃える）で描く。帯の長さは字の数で見積もり、行分けの `measureText` を呼ばない。拡大して 3 実ピクセル以上になれば今までどおり文字を描く。PNG の書き出しとサムネイルは今までどおり文字を描く。
- 不透明度と描画モードを変えないノード・塗り・線は save / restore で囲まず、変換行列だけを戻す（兄弟ごとに 1 回取っておいた行列を数で `setTransform` に渡す。DOMMatrix のまま渡すと 1 回ごとに重く、かえって遅くなった）。
- 書体は 1 回だけ代入する（不正な書体名かどうかを指定ごとに覚える）。書体ごとの上下の高さ（`measureText('')`）を覚える。
- CPU プロファイル（large、全体表示のまわりのズーム 10 回）: ズームして止まってからの 1 回が約 34ms → 約 22〜23ms。うち図形を描く `renderScene` が約 25ms → 約 17ms、描いた絵を取っておく写し（描画の命令を画素にする時間を含む）が約 8ms → 約 4ms。文字を描かないと約 9ms 減ることを確かめてから帯にした（影は外しても 1ms 未満で、効いていなかった）。
- 画素の比べ: save / restore を省くと変換行列の丸め方が変わり、拡大した表示でも文字の縁などに 1〜数十階調の違いが数百〜千画素ほど出る（位置のずれは 1e-6px 未満で、見ても分からない）。
