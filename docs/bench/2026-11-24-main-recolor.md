# 計測（2026-11-24、元のコンポーネントの色を変えたときの同期）

`npm run bench` の結果（`bench/out/latest.md` をそのまま写したもの）。値は操作 1 回ぶんのメインスレッドの時間（ms）。測り方は `bench/run.mjs` と `cli/bench/` の先頭のコメント。
その前の移り変わりは `2026-11-24-store-preview.md`・`2026-11-22-perf-rest-3.md` ほか。

- 環境: darwin arm64、Node v24、Chrome（ヘッドレス）、1440×900、deviceScaleFactor 2。同じマシンで続けて測った（並行して別の処理も動いていたので、値は揺れる。今回触っていない行の差は揺れ）
- medium と large を別々に測った（`--preset medium`、`--preset large`）。直す前は直前の main で測った

主な行（中央値、ms。medium / large）:

| 操作 | 直す前 | 直した後 | 効いたもの |
| --- | ---: | ---: | --- |
| 元の色を変える（同期と描き直し）editor | 9.1 / 63 | 7.5 / 54 | 下の全部。残りの大半は全部の描き直し（large で約 26ms）と、描いた絵の写し（約 8ms） |
| ストアの apply 1 回（元の色を変えた）Node | 2.8 / 19 | 1.8 / 12 | 同上 |
| syncComponents（元の色を変えた）Node | 2.5 / 19 | 1.8 / 11 | 同上 |
| syncComponents（元に関係ない変更）Node | 0.76 / 5.2 | 0.43 / 3.3 | インスタンスの一覧の引き継ぎ |

- 写しのあるべき姿といまの写しを比べるとき、元で参照が変わったノードの写しから比べる。食い違いはふつうそこにあるので、残りを比べずに済む（比べる順が変わるだけで答えは同じ）。
- 値の比べを、JSON の文字列を作らずに同じ答えを出す比べにした。
- 全部のインスタンスを見るとき、ノードの表の全部の id を並べ直さず、表ごとに覚えたインスタンスの一覧（表のキーの並びの順）を引き継ぐ。インスタンスでないノードだけが変わった表は前の一覧のまま、同期で作り直した表は作り直したインスタンスを後ろへ回す。
- 残り: ノードの表の写し（large で 1 回約 2.7ms、色を変える操作と同期で 1 回ずつ）と、写し 6,000 個が変わるので画面の全部を描き直す時間。
