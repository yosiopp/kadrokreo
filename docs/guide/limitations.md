# 未対応

[ユーザーズガイド](README.md) の一部。今はできないこと。

- 線に沿う文字（`textPath`）は 1 行だけ（改行は空白になる）。閉じた線でも折り返さず、線からはみ出した文字は描かない。線の反対側に並べる指定（`side="right"`）・文字の間隔の指定（`method`・`spacing`・`textLength`）は取り込まない。沿わせた線はテキストが写して持つので、元の図形を動かしてもテキストは変わらない。文字を書き換える入力欄はまっすぐ並べて出す
- テキストのアウトライン化とテキストを入れたブーリアン演算は、kdr に埋め込んだ書体のテキストだけ（OS の書体の字の形は読めない）。合字などの字の置き換え・書体に無い太さを太字に見せかける描き方・書体に無い文字の補いは再現しない
- マスクの当たり判定は、不透明度・明るさのマスクでも形（テキストは文字の形、画像・フレームは枠）で決める（透けている所や、画像の透明な所でも当たる）
- viewer の CSS で、画像を含むマスクの `mask-image` は画像を data URI で埋め込む（長くなる）
- SVG の取り込みで表せないもの（図形がいくつもあるグラデーションのマスク（形だけかける）、フィルタ、`text` の外の `textPath`、外部の画像、`:has()` や疑似要素などの CSS のセレクタ、`stroke-miterlimit`、傾けた円形のグラデーション）
- SVG 書き出しと viewer の HTML・CSS に入れられる書体は kdr に埋め込んだ書体だけ（OS の書体は名前だけなので、開く環境に書体がなければ別の書体になる）。書体のファイルは使う字に絞らずそのまま入れるので、大きな書体（日本語など）を使うと SVG・HTML のファイルも大きくなる（WOFF2 の書体ならいちばん小さく済む）。文字の基線は書き出した環境の書体の高さで置くので、別の環境で取り込み直すと書体の高さの違いだけ上下にずれることがある。1 行だけのテキストは行の高さを読み戻せない（文字の位置は揃う）
- 影ごとの描画モードは viewer の CSS では表せない（ふつうに重ねて書く）。SVG 書き出しでは影を別の要素に分けて混ぜるが、半透明か描画モードを持つ図形では図形の中だけで混ざる
- 半透明のフレームの「通過」は、子が重なるとき SVG・CSS で表せず、中身をまとめてから半透明にする。子が重ならなければ不透明度を子に配って同じ見た目で書く
- 回した図形への吸着（スナップ）は、囲む矩形の端と中央に対してだけ効く。影のずれは回転に従わない
- viewer の CSS の切り抜きの拡大は `object-view-box` で出す（対応していないブラウザでは拡大されない）
- 1 つのテキストの中での部分的な装飾（字間・下線・取り消し線はテキスト全体にかかる。SVG の取り込みで `tspan` だけに付いたものは、知らせて落とす）。上線（`overline`）と、下線と取り消し線の両方
- 下線・取り消し線の位置と太さは、文字の大きさから決める（書体の下線の情報は読まない）。SVG 書き出しと viewer の CSS はブラウザの `text-decoration` に任せるので、線の位置と太さが 1px ほど違うことがある。線に沿う文字の装飾は、文字ごとに送り幅の分の線を引く
- インスタンスごとの上書きのうち形や並びに関わるもの（大きさ、位置、行の高さ、行揃えなど）
