# kdr（kadrokreo のデザインファイルを扱うコマンド）

kdr ファイルは、ドキュメントの JSON と画像をまとめた tar.gz。中を直接書き換えず、kdr コマンドで扱う（値を検証するので壊れたファイルを書き出さない）。

## 呼び方

kdr は Docker イメージの中にある。いつもこの形で呼ぶ:

```sh
docker run --rm -i -v "$PWD:/work" --user "$(id -u):$(id -g)" ghcr.io/yosiopp/kadrokreo kdr <引数…>
```

- イメージ名は既定で公開イメージの `ghcr.io/yosiopp/kadrokreo`（無ければ `docker run` が取ってくる）。利用者が手元でビルドしたもの（`kadrokreo`）や別の名前・タグを使っていれば、それに合わせる。プロジェクトの AGENTS.md / CLAUDE.md に書いてあればそれに従う
- `-i` は付け、`-t` は付けない
- ファイルは今のディレクトリ（コンテナの `/work`）からの相対パスで指す。外のファイルは見えない
- 入力は `-f ファイル.kdr`、上書きは `-w`、別名で保存は `-o 出力.kdr`。新しく作るときは先頭を `new`
- いくつもの変更は `+` でつないで 1 回の実行にまとめる（Docker の起動が 1 回で済む）
- 終了コードは 0 成功・1 エラー・2 使い方の誤り。エラーは標準エラーに `kdr: …` で出て、何も書き出さない

## MCP のサーバー（kdr mcp）がつながっているとき

道具に kdr の MCP のサーバー（`open`・`run`・`png`・`save`・`help`）があれば、`docker run` の代わりにそれを使う（コンテナの起動がなく、PNG を画像のまま受け取れる）。
`open` で開く（新しく作るなら `run` で `new` / `build`）→ `run` の `args` にコマンドと引数の配列を渡す（`-f`・`-o`・`-w` は使わない）→ `png` で見た目を確かめる → `save` で保存。
変更は `save` するまでファイルに残らない。書き方は `help` で読む。

サーバーはこのプラグインでは登録しない。利用者が頼んだときだけ、そのプロジェクトに足す（コマンドは `kdr docs` の「MCP のサーバー」）。

## 最初にすること

使い始める前に、全体のリファレンスを読む（Docker 越しの注意・ノードの指定・JSON で出せるコマンド・すべてのコマンドと例が載っている）:

```sh
docker run --rm ghcr.io/yosiopp/kadrokreo kdr docs
```

1 つのコマンドの説明と例は `kdr help コマンド`（または `kdr コマンド --help`）。

## 進め方

1. 調べる: `kdr -f a.kdr ls`（木）、`ls --json`、`get ノード`（設定の JSON）、`find 文字`
2. 変える: `kdr -f a.kdr -w set ノード 名前=値…`、`add`、`instance` など。作るノードには `--id` を付け、その id で指すと確実。
   画面をまるごと組み立てるときは、ノードの木を XML のマークアップに書いて `kdr build 設計.xml -o a.kdr`（今の kdr に足すなら `place`）。書き方は `kdr docs` の「マークアップ」
3. 確かめる: `get` で値を、`png ノード --to 出力.png` を書き出して画像で見た目を確かめる（SVG なら `svg-out ノード --to -` を読む）
